# 03 数据设计

> 项目:GalleryHub —— Obsidian 美术资产画廊插件
> 日期:2026-08-10
> 状态:草案

## 1. 设计原则

1. **数据独立于插件**:gallery.json 是公开、带版本号的纯文本契约,任何工具都能读取
2. **资产原件神圣不可侵**:插件只登记路径,绝不修改/移动/删除已入库的原件(导入时的"复制进 assets/"是唯一写入场景)
3. **数据与展示分离**:资产元数据(prompt 等)与画布布局(位置尺寸)分层存储,同一资产可上多个画布
4. **同步友好**:2 空格缩进格式化;条目按 id 稳定排序,减小同步 diff

## 2. 目录结构

```
GalleryHub/                     # Obsidian 仓库内
├── gallery.json                # 唯一数据库
├── gallery.json.bak            # 写前自动备份(插件维护)
├── assets/                     # 资产原件,按年月分桶避免单目录爆炸
│   ├── 2026-08/
│   │   ├── a1b2c3d4.png
│   │   └── e5f6a7b8.mp4
│   └── ...
└── .thumbs/                    # 缩略图缓存(可再生,预留,V2/V3)
```

- 入库文件重命名为 `{id}.{ext}`,原始文件名保存在条目 `fileName` 字段
- `.thumbs/` 内容可随时删除重建,不属于需备份数据

## 3. gallery.json Schema

```jsonc
{
  "version": 1,                  // schema 版本,迁移依据
  "boards": {                    // 画布注册表
    "b-default": {
      "name": "默认画布",
      "createdAt": "2026-08-10T12:00:00+08:00"
    }
  },
  "items": [ /* GalleryItem[] */ ]
}
```

### 3.1 GalleryItem

```jsonc
{
  // ---- 身份 ----
  "id": "a1b2c3d4",              // nanoid(8),全局唯一,兼作资产文件名
  "type": "image",               // "image" | "video" | "link"
  "createdAt": "2026-08-10T12:00:00+08:00",   // 入库时间
  "modifiedAt": "2026-08-10T12:00:00+08:00",

  // ---- 资产定位(按 type 二选一)----
  "path": "GalleryHub/assets/2026-08/a1b2c3d4.png",  // image/video:仓库相对路径
  "url": null,                   // link:外部 URL
  "fileName": "原始文件名.png",   // 导入前的原名,便于溯源
  "hash": "sha256:...",          // 文件哈希,重复检测用(V3,可为 null)

  // ---- 描述 ----
  "title": "",
  "note": "",                    // 自由备注,Markdown
  "tags": ["人物", "赛博朋克"],
  "rating": 0,                   // 0-5,0 表示未评分
  "source": "",                  // 来源链接:参考图出处/原帖/教程等

  // ---- AI 生成元数据(非 AI 资产全部留空)----
  "gen": {
    "prompt": "",
    "negativePrompt": "",
    "model": "",                 // "flux-dev" / "sd-xl" / "midjourney-v7" ...
    "seed": "",
    "steps": null,
    "cfg": null,
    "sampler": "",
    "size": "",                  // "1024x1024"
    "extra": {}                  // 未归类参数原样保留(如 ComfyUI 节点信息)
  },

  // ---- 画布布局:boardId → 位置 ----
  "layouts": {
    "b-default": { "x": 100, "y": 200, "w": 320, "h": null, "z": 3 }
    // h 为 null 时按资产宽高比自动;z 为叠放次序
  }
}
```

### 3.2 字段约定

| 字段 | 必填 | 说明 |
|---|---|---|
| id / type / createdAt | ✓ | 缺失视为损坏条目,加载时告警跳过 |
| path | image/video ✓ | 必须位于 `GalleryHub/assets/` 下 |
| url | link ✓ | http(s) 协议 |
| gen.* | ✗ | 整个 gen 对象可省略;`extra` 兜底存放解析不了的参数 |
| layouts | ✗ | 空对象 = 不在任何画布上,仅出现在网格画廊 |

### 3.3 标签

- 扁平字符串数组,V1 不做层级;支持 `父/子` 命名约定作为软层级,筛选器按前缀分组展示
- 全部标签从 items 动态聚合,不单独维护标签表(避免两处数据不一致)

## 4. 写入与一致性

| 场景 | 行为 |
|---|---|
| 常规保存 | 防抖 500ms → 序列化全量 → 写 `gallery.json.tmp` → 覆盖正式文件(近似原子) |
| 写前保护 | 复制现有文件为 `.bak`(每次会话首写一次) |
| 加载失败 | JSON.parse 异常 → 只读模式 + 提示从 .bak 恢复,绝不自动覆盖 |
| 外部修改 | vault modify 事件且非本插件写入 → 提示"重新加载数据" |
| OneDrive 冲突副本 | 启动扫描 `GalleryHub/gallery*-*.json` 模式文件,发现即提醒手动合并 |

## 5. 版本迁移

- `version` 字段自增;插件内维护 `migrations: {1→2: fn, ...}` 链式升级
- 迁移前强制备份为 `gallery.v{n}.bak.json`
- 插件读到高于自身支持的 version → 只读模式,提示升级插件

## 6. 与 Obsidian 生态的互操作(预留)

- 条目可选字段 `noteLink`(未列入 V1 schema):关联仓库内某篇 md 深度笔记
- 导出:提供命令将筛选结果导出为 Markdown 图集(`![[...]]` 列表),供普通笔记引用
- gallery.json 本身可被 Dataview(dv.io.load)读取,用户可自行写查询
