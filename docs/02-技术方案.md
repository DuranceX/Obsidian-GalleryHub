## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript | Obsidian API 官方类型支持(obsidian.d.ts) |
| 构建 | esbuild | 官方 sample plugin 同款,毫秒级增量编译 |
| UI | **原生 DOM,零框架** | 插件体积小、无依赖升级负担;Obsidian API 本身提供 createEl 等 DOM 工具;网格+画布交互用原生实现完全够用 |
| 状态管理 | 单例 Store + 事件订阅 | 数据量级(千条)无需引入库 |
| 样式 | 单文件 styles.css + Obsidian CSS 变量 | 自动适配明暗主题 |
| 测试 | 手动为主;png-meta 等纯函数配 vitest | 性价比 |

## 3. 关键设计决策

### 3.1 视图:ItemView 而非 iframe HTML

插件注册自定义视图类型 `gallery-hub-view`:

```ts
this.registerView(VIEW_TYPE, (leaf) => new GalleryView(leaf, this.store));
this.addRibbonIcon('layout-grid', 'GalleryHub', () => this.activateView());
```

- 与 Canvas / Excalidraw 同级的标签页体验
- 直接访问 Vault API,**无 CORS / 沙箱问题**(此前 HTML 方案的根本痛点)
- 可注册多个视图实例(如画廊 + 画布各开一个标签)

### 3.2 数据读写:Vault API + 原子保护

- 读:`vault.adapter.read('GalleryHub/gallery.json')` → JSON.parse → 内存 Store
- 写:防抖(500ms)合并写入;写前将旧文件复制为 `gallery.json.bak`
- 外部变更(OneDrive 同步进来):监听 `vault.on('modify')`,若非本插件写入则提示重载
- **冲突低风险化**:JSON 带缩进格式化,便于同步工具做行级 diff;所有写入均全量序列化

### 3.3 资产展示:resource URL

```ts
const url = this.app.vault.adapter.getResourcePath(item.path);
imgEl.src = url;   // app:// 协议,Electron 原生加载,无需读入内存
videoEl.src = url; // <video> 同理,V1 即支持
```

- 缩略图策略 V1:直接用原图 + CSS `object-fit`,配合 IntersectionObserver 懒加载
- 千级以上卡顿时再引入:生成 `GalleryHub/.thumbs/` 缩略图缓存(canvas 缩放,V2/V3 观察后决定)

### 3.4 无限画布(V2)

- 单个绝对定位容器 + CSS transform(translate + scale)实现平移缩放
- 卡片位置存于条目的 `boards[boardId]`(见 03-数据设计),拖拽结束才写库
- 不引入 canvas 2D 渲染——DOM 元素即卡片,天然支持 video / iframe / 文本混排

### 3.5 PNG 生成参数解析(V3)

- A1111:PNG tEXt chunk `parameters`,纯文本格式,正则拆分正/负向提示词与参数行
- ComfyUI:tEXt chunk `prompt` / `workflow`,JSON 格式,遍历节点提取 CLIPTextEncode 等
- 自实现轻量 PNG chunk 读取(仅需遍历 chunk 头,~100 行),不引第三方库
- JPEG(如 Midjourney 下载图)含 EXIF/XMP 时按需支持,优先级低

## 4. 构建与部署流程

```jsonc
// package.json scripts
{
  "dev":    "node esbuild.config.mjs",            // watch 模式,产物直接输出到仓库插件目录
  "build":  "node esbuild.config.mjs production",
  "deploy": "node scripts/deploy.mjs"             // 复制 manifest/main.js/styles.css 到插件目录
}
```

- **开发**:esbuild watch 的 outfile 直接指向 `C:\...\Obsidian\.obsidian\plugins\gallery-hub\main.js`,配合社区插件 Hot-Reload 实现改码即生效
- **发布**:`npm run build && npm run deploy`;其他设备经 OneDrive 收到成品即可用,无需 Node 环境
- 插件目录路径写在 `.env` / deploy 脚本常量中,便于换机

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| OneDrive 同步冲突产生 gallery.json 副本 | 带 .bak 备份;启动时检测 `gallery*.json` 冲突副本并提示合并 |
| 大量 mp4 导致画廊卡顿 | 视频卡片默认只渲染 poster 帧(preload="metadata"),悬停才播放 |
| Obsidian API 升级破坏兼容 | manifest 锁定 minAppVersion;跟随官方 sample plugin 的 API 用法 |
| 数据文件损坏 | 写前备份 + JSON.parse 失败时拒绝覆盖并引导恢复 .bak |
